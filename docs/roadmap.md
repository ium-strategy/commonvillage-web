# 남은 작업

이 프로토타입이 못 하는 것과, 실서비스 전에 결정하거나 만들어야 할 것들입니다.

## 1. 실데이터로 교체 (선행 조건)

[`assets/data.js`](../assets/data.js)의 지역 5곳·공고 15건은 **전부 화면 검증용 예시**입니다.

- [ ] MVP 지역 3~5곳 확정 (기획서 미결 #4)
- [ ] 6지표 × 지역 수 = 수동 셀 입력. `source` · `asOf` · `cycle` · `version` 을 반드시 채울 것
- [ ] 공고 20~30건 등재 — 수집 → 구조화 초안 → 사람 검수 → 게시
- [ ] `pastResult`(경쟁률)는 확보된 공고만. 없으면 필드를 두지 말 것
- [ ] 모든 페이지 상단의 검은 프로토타입 고지 바 제거
- [ ] `SITE.kakaoChannelUrl` 채우기 (채널 개설 후)
- [ ] G-10 '수행 역량' 블록을 실제 실적으로 교체 — 지금은 "[작성 필요]" 상태

## 2. 백엔드와 발송 인프라

지금은 알림 신청·문의·구독·오류 신고·이벤트 로그가 전부 브라우저 `localStorage`에만 쌓이고 어디로도 전송되지 않습니다.

맞춤 알림이 실제로 동작하려면 서버에 세 가지가 필요합니다.

1. **판정 배치** — 새 공고 등재 시 저장된 StayProfile 전체에 판정을 돌려 '신청 가능'만 추림
2. **발송** — 시즌 중 주 1회 묶음 + 마감 D-3 개별. **보낼 공고가 0건이면 발송 생략**
3. **원클릭 수신거부**

이 발송 인프라가 그대로 G-10의 유료 상품 '타깃 알림'이 됩니다. 별도 개발이 필요 없으므로 백엔드 착수 시 1순위로 잡는 것이 낫습니다.

그 밖에 서버로 옮겨야 할 것: 익명 ID ↔ 이메일 병합, 판정 오류 신고 접수, B2G 문의·리포트 구독, 이벤트 수집.

## 3. 서버 렌더링 (SEO)

기획서 §9에서 SEO 서버 렌더링을 '권장'이 아니라 **기술 요구사항**으로 승격했습니다.
검색이 제1 유입 채널이기 때문입니다. 이 프로토타입은 그 요구를 충족하지 못합니다.

- 공고·지역·지난모집 페이지는 서버에서 렌더링해야 합니다
- 페이지별 `<title>` / `<meta description>`은 이미 다르게 넣어 두었지만, `region.html`과 `program.html`은 JS가 런타임에 채웁니다 — 크롤러 기준으로는 비어 있는 것과 같습니다
- 시즌 SEO 콘텐츠(권역별·목적별 5~10편/시즌)를 담을 자리가 아직 없습니다
