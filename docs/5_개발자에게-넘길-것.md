# 5. 개발자에게 넘길 것

**개발자를 만났을 때 이 문서를 그대로 보여주시면 됩니다.**
지금 사이트가 무엇을 못 하는지, 무엇부터 만들어야 하는지 순서대로 정리했습니다.

---

## 한 줄 요약

지금 것은 **화면만 있는 시안**입니다. 보기에는 완성된 사이트 같지만, 뒤에서 정보를 받아 저장하고
메일을 보내는 부분(서버)이 아예 없습니다. 그래서 **알림을 신청해도 메일이 나가지 않습니다.**

---

## 담당자가 먼저 해야 할 일 (개발 아님)

개발을 시작하기 전에 채워 넣어야 하는 것들입니다.

- [ ] **어느 지역으로 시작할지 3~5곳 확정**
- [ ] 그 지역들의 6가지 점수 채우기 (출처와 기준일까지)
- [ ] **공고 20~30건 등재** — 공고 찾기 → 쉬운 말로 정리 → 사람이 검수 → 올리기
- [ ] 지난 경쟁률은 **확인된 공고만** 채우기
- [ ] `for-gov.html`의 **"수행 역량" 부분을 실제 실적으로 교체** (지금 "[작성 필요]" 상태)
- [ ] 카카오톡 채널 개설하고 주소 넣기
- [ ] **모든 화면 맨 위 검은 띠(예시 데이터 안내) 제거** — 진짜 정보로 다 바꾼 뒤에

방법은 [2. 직접 고칠 수 있는 것](2_직접-고칠-수-있는-것.md)에 있습니다.

---

## 개발자에게 맡길 것 — 우선순위 순서

### 1순위. 알림 발송 기능

**이게 없으면 서비스의 핵심이 작동하지 않습니다.** 세 가지가 필요합니다.

1. **골라내기** — 새 공고가 올라오면, 저장된 사람들의 조건에 하나씩 대보고 "신청 가능"인 사람만 추리기
2. **보내기** — 시즌 중 주 1회 묶음 발송 + 마감 3일 전 개별 발송.
   **보낼 공고가 0건이면 발송을 건너뛰어야 합니다**
3. **해지** — 메일 아래 링크를 한 번 누르면 바로 해지

> **여기에 사업적으로 중요한 점이 하나 있습니다.**
> 이 발송 기능이 그대로 **지자체에 파는 유료 상품 "타깃 알림"** 이 됩니다.
> 따로 개발할 필요가 없다는 뜻이라, 이걸 먼저 만드는 게 B2C와 B2G 양쪽에 다 이득입니다.

### 2순위. 검색에 걸리게 만들기 (SEO)

기획서에서 **검색이 첫 번째 유입 경로**라고 정했습니다. "한달살기 지원사업"을 검색했을 때 우리가 나와야 합니다.

지금 사이트는 공고 목록과 지역 정보를 **브라우저에서 그려 냅니다.**
사람 눈에는 보이지만 **검색 로봇 눈에는 빈 페이지로 보입니다.** 이걸 서버에서 미리 그려 내보내도록 바꿔야 합니다.

개발자에게 이렇게 말씀하시면 됩니다.
**"공고·지역·지난모집 페이지를 서버 사이드 렌더링으로 바꿔 주세요."**

### 3순위. 정보 저장 기능

지금은 아래 내용이 전부 방문자 브라우저에만 남고 우리에게 오지 않습니다.

- 알림 신청 (이메일·조건)
- 지자체 문의, 리포트 구독 신청
- 판정 오류 신고
- 방문자 행동 기록 (몇 명이 진단했는지, 몇 명이 신청 페이지로 갔는지)

**마지막 항목이 특히 중요합니다.** 이게 없으면 지자체에 보낼 성과 리포트의 숫자를 만들 수 없습니다.

## 아직 결정하지 못한 것

개발과 별개로 **경영 판단이 필요한** 항목입니다.

| 무엇 | 상태 |
|---|---|
| 유료 노출 자리를 얼마에 팔 것인가 | 미정 — 화면은 이미 준비됨 |
| 개인정보 관련 법무 검토 | 미정 — 특히 참여의향 수집과 카카오 채널 동의 |
| 6가지 점수를 시·군·구 단위로 구할 수 있는지 확인 | 미정 |
| 공고 페이지에 검색용 특수 표시(JobPosting)를 넣을지 | 미정 — 지원사업에 이 방식이 맞는지 판단 필요 |

---

## 이 사이트에 없는 것 — 별도 작업

**「체류사업 공고 점검」** (매주 월요일 아침, 나라장터와 지자체 공고를 훑는 자동화)은
방문자가 보는 화면이 아니라 **우리 내부 영업용 작업**이라 이 폴더에 들어 있지 않습니다.

결과물이 화면이 아니라 영업 리스트와 「전국 체류형 지원사업 모집 현황 리포트」로 가기 때문에,
별도 폴더나 별도 저장소로 관리하는 편이 맞습니다.

## 참고: 전체 일정 (기획서 기준)

| 시기 | 할 일 |
|---|---|
| 2026년 11월 | 웹사이트 공개 — 화면 11개, 지역 3~5곳, 공고 20~30건 |
| 2027년 1~3월 | 첫 시즌 대응 — 공고 늘리기, 검색 콘텐츠, 유료 노출 시작 |
| 2027년 2월까지 | 공공데이터 연동, 지역 20곳으로 확대 |
| 지자체 3곳 넘으면 | 지자체가 직접 공고를 올리는 기능, 회원 시스템 |
| 2027년 하반기 | 앱을 만들지 결정 |

**앱은 아래 세 가지 중 두 개가 충족될 때만 만듭니다.**

1. 알림 등록자가 시즌당 1,000명 넘음
2. 알림을 받고 다시 들어오는 사람이 의미 있게 많음
3. 지자체 매출로 개발비를 회수할 구조가 생김

저빈도 서비스에서 앱을 먼저 만들면 비용만 커집니다.
