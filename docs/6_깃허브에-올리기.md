# 6. 깃허브에 올리고 웹에 공개하기

## 깃허브가 뭔가요

**파일을 보관하고, 누가 언제 뭘 고쳤는지 기록이 남는 인터넷 창고**입니다.

- 실수로 잘못 고쳐도 **예전 상태로 되돌릴 수 있습니다**
- 담당자가 바뀌어도 파일과 기록이 그대로 넘어갑니다
- 개발자에게 주소 하나만 주면 됩니다

---

> ## ⚠ 이 저장소는 공개(Public)입니다
>
> 사이트를 인터넷에 공개하기 위해 저장소를 공개로 전환했습니다.
> **여기 올라간 것은 이 폴더의 문서를 포함해 누구나 볼 수 있습니다.**
>
> 그러니 앞으로 아래 것들은 **절대 이 폴더에 넣지 마세요.**
>
> - 비밀번호, 접속 키, 인증 토큰
> - 신청자 명단, 이메일 주소 등 개인정보
> - 계약서, 견적서, 단가표
> - 대외비로 다뤄야 할 사업 자료
>
> 그런 파일은 이 폴더 바깥에 따로 보관하세요.

## 사이트를 웹에 공개하기 (한 번만)

1. GitHub Desktop에서 **Push origin** 을 눌러 최신 상태를 올립니다
2. **`Ctrl + Shift + G`** 로 저장소 페이지를 엽니다
3. **Settings → General** → 맨 아래 **Danger Zone**
   → **Change repository visibility** → **Change to public** → 확인 문구 입력
4. **Settings → Pages** 로 이동
5. **Build and deployment** 에서
   - Source: **Deploy from a branch**
   - Branch: **main**, 폴더: **/ (root)**
   - **Save**
6. 1~2분 뒤 같은 화면 위쪽에 초록색으로 주소가 뜹니다

> 무료 플랜에서는 **저장소가 공개여야만** 이 기능을 쓸 수 있습니다.
> 비공개로 두고 사이트만 공개하려면 유료 플랜이 필요합니다.

## 파일을 고쳤을 때 (매번 반복)

공고를 추가하거나 문구를 바꾼 뒤:

1. GitHub Desktop을 엽니다 → 고친 파일이 왼쪽에 목록으로 뜹니다
2. 왼쪽 아래 칸에 **무엇을 고쳤는지 한 줄** 씁니다 (예: `강릉 공고 마감일 수정`)
3. **Commit to main** 을 누릅니다
4. **Push origin** 을 누릅니다

**1~2분 뒤 웹사이트에도 자동으로 반영됩니다.** 따로 할 일은 없습니다.

> 2번 설명을 성의 있게 적어 두세요. 나중에 "언제 뭘 바꿨더라" 찾을 때 이게 전부입니다.
> `수정`이라고만 적으면 아무 도움이 안 됩니다.

## 자주 겪는 문제

**"사이트 주소로 들어갔는데 404가 떠요"**
→ 첫 배포는 1~2분 걸립니다. 조금 기다렸다 새로고침하세요.
→ 그래도 안 되면 Settings → Pages 에서 Branch가 `main`, 폴더가 `/ (root)`인지 확인하세요.

**"고쳤는데 사이트에 반영이 안 돼요"**
→ Commit만 하고 **Push origin**을 안 눌렀을 가능성이 큽니다.
→ Push 후에도 1~2분 걸립니다.

**"화면이 깨져 보여요"**
→ `assets` 폴더가 함께 올라갔는지 확인하세요. 이 폴더가 없으면 디자인이 전부 사라집니다.

**"Publish 버튼이 안 보여요"**
→ 이미 올라간 상태입니다. 대신 `Push origin` 버튼을 쓰세요.

**"실수로 비밀 파일을 올렸어요"**
→ 파일만 지우는 걸로는 부족합니다. **과거 기록에 남아 있습니다.**
→ 해당 비밀번호·키를 즉시 폐기하고 새로 발급받으세요. 그게 가장 확실합니다.
