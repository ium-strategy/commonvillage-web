# 리텐션 훅

근거: `CommonVillage_리텐션훅_추가본_v1.0` (2026.09.03). 이 문서가 기존 C-08 명세를 대체합니다.

> 저빈도 서비스의 리텐션은 "자주 오게"가 아니라
> **조건을 받아두고, 맞는 공고가 뜨면 우리가 먼저 부른다**로 만든다.

핵심 기능은 **자격 맞춤 알림**, 보조 훅은 **경쟁률 데이터**와 **다시 열리면 알림**입니다. 셋 다 구현했습니다.

---

## ① 자격 맞춤 알림 (핵심)

화면 표기 기능명은 **맞춤 공고 알림**, 핵심 문구는 "전체 공지가 아니라, 당신이 신청할 수 있는 공고만 보냅니다."

### 쓰는 법

화면에 이 한 줄만 두면 [`assets/app.js`](../assets/app.js)가 그리고 이벤트까지 묶습니다.

```html
<div data-subscribe="foot"></div>
```

| 속성 | 뜻 |
|---|---|
| `data-subscribe` | `mid`(목록 사이) · `foot`(하단) · `reopen`(종료 공고 재공고 알림) |
| `data-region` | 그 지역 공고로 한정해 등록 |
| `data-program` | 그 공고의 마감 D-3 알림까지 함께 등록 |
| `data-title` / `data-lead` | 카피 직접 지정 |

동적으로 그리는 화면(공고 상세·지역 상세·목록)에서는 마크업을 넣은 뒤 `CV.mountSubscribes()`를 한 번 부릅니다.
이미 그려진 블록은 다시 마운트되지 않습니다.

### 동작 규칙

- **진단 프로필이 있으면** 블록에 내 조건 요약이 함께 뜹니다 — "내 조건 일하며 지내기 · 2~4주 · 서울특별시 거주에 맞는 공고만 골라 보내드립니다"
- **없으면** 1분 진단으로 유도합니다. 조건이 없으면 맞춤 발송이 불가능하기 때문입니다
- **이메일 한 줄 + 수신 동의 체크 1개.** 동의 없이는 제출되지 않습니다
- **이미 등록한 방문자**에게는 폼 대신 확인 상태를 보여 줍니다. 페이지마다 반복해 조르면 해지율(가드레일)이 올라갑니다
- 목록 중간 삽입은 **카드가 5개 이상일 때만** 나옵니다. 짧은 목록을 비집고 들어가지 않습니다

### 배치

| 화면 | 위치 |
|---|---|
| 홈 | 공고 목록 아래 + 페이지 하단 |
| 목적 선택 | 하단 — 진단을 시작하지 않고 나가는 방문자용 |
| **추천 결과** | **하단 — 제1 수집 지점. 프로필과 이메일이 만나는 곳** |
| 지역 상세 | 하단, 그 지역으로 한정 |
| 공고 목록 | 3번째 카드 뒤 + 페이지 하단 |
| 공고 상세 | 하단, 그 지역·공고로 한정 |
| 관심 목록 | 하단 |
| 지난 모집 | 카드마다 버튼 |

진단 6단계에는 넣지 않았습니다. 진행을 끊습니다.

추천 결과 블록의 카피에는 실제 신청 가능 건수가 들어갑니다.

> 지금은 신청 가능한 사업이 **2건**이에요. 전체 공지가 아니라, 당신이 신청할 수 있는 공고만 보냅니다.

0건이면 시즌 공백기 카피로 자동 전환됩니다 — "다음 모집 시즌은 보통 1~3월·7~9월이에요."

### 발송 규칙 (화면에 약속한 것)

1. 자격 '신청 가능' 판정이 난 새 공고를 **시즌 중 주 1회 묶음**으로
2. 관심 표시한 공고의 **마감 3일 전** 개별 알림
3. 시즌 시작 안내(연 2회)

판정이 불확실한 공고는 '확인 필요'라고 그대로 적어 보냅니다.
전체 공고를 일괄로 보내는 뉴스레터는 만들지 않습니다.

> 주의: 주 1회 묶음은 **보낼 공고가 있을 때만** 성립합니다.
> 발송 배치에 "보낼 공고 0건이면 발송 생략" 조건이 없으면 빈 메일이 나가고 해지율이 올라갑니다.

## ② 경쟁률·선정 데이터

공고 상세 '한눈에' 표에 한 줄이 들어갑니다.

> **지난 모집** 2026 상반기 1기 · 20명 모집 · 신청 96명
> 출처: 강릉시 결과 공고

`Program.pastResult`가 있는 공고에만 나오고, **없으면 행 자체를 그리지 않습니다.** 추정치를 만들지 않습니다.
시드에는 확보를 가정한 2건만 넣었습니다. 실제로도 파일럿 사업 1~2건부터 시작해 있는 것만 정확하게 채우면 됩니다.

이 데이터는 지자체 홈페이지의 결과 공고와 파일럿 지자체 제공으로 모읍니다.
커먼빌리지에만 있는 콘텐츠가 되므로 링커리어의 '합격 자소서'에 해당하는 자리입니다.

## ③ 다시 열리면 알림

지난 모집 탭의 종료 카드마다 **「다시 열리면 알림 받기」 버튼**이 붙습니다.
누르면 페이지 이동 없이 그 자리에서 인라인 폼이 열리고, 등록하면 `type: "reopen"`으로 저장됩니다.
공고 상세도 종료 상태면 같은 블록이 뜹니다.

체류지원사업은 해마다 다시 열리는 경우가 많아, 시즌 공백기 이탈을 막는 장치로 씁니다.
재공고 등재 시 자동 발송할 문구는 이렇습니다.

> 작년에 관심 두셨던 ○○군 한달살기, 올해 모집이 시작됐어요.

## 카카오톡 채널

[`assets/data.js`](../assets/data.js)의 `SITE.kakaoChannelUrl` **한 곳만 채우면** 전 화면의 버튼이 동시에 연결됩니다.

```js
const SITE = {
  kakaoChannelUrl: 'https://pf.kakao.com/_xxxxx'
};
```

비어 있는 동안에는 버튼을 눌러도 이동하지 않고 "채널 준비 중입니다. 지금은 메일 주소를 남겨 주세요"로 바뀝니다.
존재하지 않는 URL을 넣어 두지 않았습니다.

> 카카오톡은 기획서 v2.0에 없던 신규 채널입니다(§2.1은 이메일 한 줄만 상정).
> 채널 개설과 별도 수신 동의 처리가 필요합니다.

## 이벤트

| 이벤트 | 시점 |
|---|---|
| `alert_opt_in` | 알림 등록. `type`이 `matched` 또는 `reopen` |
| `alert_click_through` | 알림 메일 링크로 재방문. 메일 링크에 `?src=alert&c=<캠페인>`을 달면 자동 기록 |
| `subscribe_kakao_click` | 카카오 버튼 클릭 |

`alert_email_sent`는 발송 서버 쪽 이벤트라 프런트에서 남기지 않습니다.

지표: 알림 등록 수(시즌당), 알림→재방문 전환율, **해지율(가드레일)**.

## 만들지 않은 것

커뮤니티·게시판, 출석/포인트, 앱 푸시, 전체 공고 일괄 뉴스레터.
리텐션 훅 문서 §4의 경계를 그대로 지켰습니다. B2C 리텐션은 위 세 훅이 전부입니다.
