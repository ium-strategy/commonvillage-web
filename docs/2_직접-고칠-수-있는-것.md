# 2. 직접 고칠 수 있는 것

개발자 없이 담당자가 직접 바꿀 수 있는 것들입니다.
**공고, 지역 정보, 카카오톡 주소는 전부 파일 하나에서 고칩니다.**

---

## 시작하기 전에 — 세 가지만 지켜 주세요

### ① 백업부터

고칠 파일은 `assets` 폴더 안의 **`data.js`** 입니다.
고치기 전에 이 파일을 복사해서 `data.js.백업` 처럼 이름을 바꿔 같은 폴더에 두세요.
잘못 고쳐서 화면이 안 나오면 백업 파일 이름을 다시 `data.js`로 바꾸면 원래대로 돌아옵니다.

### ② 메모장 말고 다른 걸로 여세요

윈도우 기본 메모장으로 열면 한글이 깨질 수 있습니다.
**VS Code**(무료, <https://code.visualstudio.com>)를 설치해서 여시길 권합니다. 색깔이 입혀져서 훨씬 알아보기 쉽습니다.

### ③ 기호를 건드리지 마세요

`data.js` 안에는 `{ }` `[ ]` `,` `'` 같은 기호가 많습니다. **글자만 바꾸고 기호는 그대로 두세요.**
기호 하나만 지워져도 사이트 전체가 안 나옵니다.

> 고친 뒤에는 항상 `사이트 열어보기.bat`으로 확인하세요.
> 화면이 하얗게 비어 있으면 어딘가 기호가 깨진 것입니다. 백업으로 되돌리고 다시 시도하세요.

## 공고 하나 추가하기

`data.js` 파일에서 `const PROGRAMS = [` 라고 적힌 줄을 찾으세요. 여기부터 공고 목록입니다.

공고 하나는 `{` 로 시작해서 `},` 로 끝나는 한 덩어리입니다.
**기존 덩어리 하나를 통째로 복사해서 아래에 붙여넣고, 내용만 바꾸는 것**이 가장 안전합니다.

아래는 붙여넣고 고쳐 쓸 수 있는 예시입니다.

```js
  {
    id: 'ys-work-2027',
    regionId: 'gangneung',
    title: '여수 워케이션 지원사업',
    org: '여수시 관광과',
    benefit: '숙박 50% 지원 + 공유오피스 무료, 2주~4주',
    durationTypes: ['2-4w'],
    targetSummary: '전남 외 지역 거주 성인',
    openDate: '2027-01-10',
    closeDate: '2027-02-20',
    sourceUrl: 'https://여수시공고주소',
    checkedAt: '2027-01-12',
    partner: false,
    purposes: ['work'],
    summary: [
      '공고 내용을 쉬운 말로 다시 쓴 문장입니다.',
      '두 문단까지 넣을 수 있습니다.'
    ],
    rules: [
      { type: 'residence', mode: 'exclude', sido: ['전라남도'], label: '전라남도 외 지역 거주자' },
      { type: 'age', min: 19, max: null, label: '만 19세 이상' },
      { type: 'duration', allow: ['2-4w'], label: '2~4주 체류' }
    ]
  },
```

### 각 줄이 무슨 뜻인가

| 항목 | 뜻 | 주의 |
|---|---|---|
| `id` | 공고를 구분하는 이름표 | **다른 공고와 겹치면 안 됩니다.** 영어와 숫자만 |
| `regionId` | 어느 지역 공고인가 | 아래 지역 목록의 이름표 중 하나여야 합니다 |
| `title` | 사업 이름 | |
| `org` | 공고를 낸 기관 | |
| `benefit` | 혜택 한 줄 요약 | "무엇을 얼마나 + 기간" 형태로 |
| `durationTypes` | 체류 기간 종류 | `'1w'` `'2-4w'` `'1-3m'` `'3m+'` 중에서. 여러 개면 쉼표로 |
| `targetSummary` | 대상 요약 | |
| `openDate` / `closeDate` | 모집 시작일 / 마감일 | **반드시 `2027-01-10` 형식** |
| `sourceUrl` | 원문 공고 주소 | |
| `checkedAt` | 내가 확인한 날짜 | 확인한 날로 갱신하세요 (아래 설명) |
| `partner` | 돈 받고 상단 노출하는 공고인가 | `true`면 상단 고정 + "지자체 협력" 라벨 |
| `purposes` | 어떤 목적에 맞는 공고인가 | `'work'`(일하며) `'rest'`(쉬며) `'settle'`(정착) |
| `summary` | 쉬운 말 요약 | 문장마다 따옴표로 감싸고 쉼표로 구분 |
| `rules` | 신청 자격 조건 | 아래 설명 |

### `checkedAt`(확인일)이 중요한 이유

이 날짜로부터 **14일이 지나면 화면에 "확인일 경과" 경고가 자동으로 붙습니다.**
공고를 다시 확인했으면 이 날짜를 오늘로 바꿔 주세요. 그러면 경고가 사라집니다.

### `rules`(자격 조건) 쓰는 법

원문 공고에 **적혀 있는 조건만** 넣으세요. 추측해서 넣으면 안 됩니다.

| 조건 종류 | 이렇게 씁니다 |
|---|---|
| 특정 지역 거주자는 제외 | `{ type: 'residence', mode: 'exclude', sido: ['전라남도'], label: '전남 외 거주자' }` |
| 나이 제한 | `{ type: 'age', min: 19, max: 39, label: '만 19~39세' }` |
| 나이 하한만 | `{ type: 'age', min: 19, max: null, label: '만 19세 이상' }` |
| 체류 기간 제한 | `{ type: 'duration', allow: ['2-4w'], label: '2~4주 체류' }` |
| 차량 필요 | `{ type: 'vehicle', required: true, label: '자가용 이용 가능' }` |
| 2인 이상만 | `{ type: 'companion', allow: ['couple','family','friend'], label: '2인 이상 동행' }` |
| 해석이 애매한 조건 | `{ type: 'doc', label: '수도권 거주 우대 조건 해석', needsDoc: true }` |

`label`은 화면에 그대로 나오는 문장입니다. 사람이 읽을 말로 쓰세요.

마지막 `doc` 종류를 넣으면 그 공고는 **"확인 필요"**로 판정됩니다.
공고 문구가 애매해서 우리가 확실히 판단할 수 없을 때만 쓰세요.

### 제출 서류를 안내하려면

재직증명서 같은 **서류**는 자격 조건이 아니라 준비물입니다. `rules`에 넣지 말고 따로 적으세요.

```js
    rules: [
      { type: 'age', min: 19, max: null, label: '만 19세 이상' }
    ],
    documents: ['재직증명서 또는 프리랜서 활동 증빙']
```

> 서류를 `rules`에 넣으면 그 공고가 전부 "확인 필요"로 떨어집니다.
> 그러면 "신청 가능 n건"이라는 우리 서비스의 핵심 숫자가 0이 되어 버립니다.

### 지난 경쟁률을 아는 경우에만

발주기관이 공개한 지난 회차 결과를 **확인했을 때만** 넣으세요.

```js
    pastResult: { year: 2026, round: '상반기 1기', quota: 20, applicants: 96, source: '강릉시 결과 공고' },
```

넣으면 공고 화면에 "지난 모집: 2026 상반기 1기 · 20명 모집 · 신청 96명"이 표시됩니다.
**모르면 이 줄을 아예 넣지 마세요.** 넣지 않으면 화면에 그 항목이 나오지 않습니다. 추측한 숫자를 넣으면 안 됩니다.

---

## 공고 수정·삭제

- **수정**: 해당 공고 덩어리에서 글자만 바꾸면 됩니다.
- **삭제**: `{` 부터 `},` 까지 통째로 지우세요. 중간만 지우면 안 됩니다.
- **마감된 공고는 지우지 마세요.** 마감일이 지나면 자동으로 '지난 모집' 탭으로 넘어갑니다.
  지난 모집은 검색으로 사람을 데려오는 자산이고, "다시 열리면 알림 받기"로 이어집니다.

## 지역 정보 고치기

`data.js`에서 `const REGIONS = [` 를 찾으세요.

```js
  {
    id: 'gangneung',
    name: '강릉시',
    sido: '강원특별자치도',
    tagline: '기차로 닿는 바다, 일할 자리도 있는 중소도시',
    intro: '서울에서 KTX로 2시간이 채 안 걸립니다. ...',
    caution: '7~8월 성수기에는 숙박비가 평소의 1.5배 이상으로 오릅니다.',
    metrics: {
      life:    m(78, '시내권 도보 생활 가능', '소상공인시장진흥공단 상가정보', '2026-08-20', '월'),
      ...
    }
  },
```

| 항목 | 뜻 |
|---|---|
| `tagline` | 지역 카드에 나오는 한 줄 소개 |
| `intro` | 지역 상세 화면의 설명글. **관광지 나열 말고 생활 이야기로** (장보기·병원·이동) |
| `caution` | 알아둘 점 한 줄. 단점을 솔직히 적는 자리입니다 |
| `metrics` | 6가지 점수 (아래 설명) |

### 6가지 점수 고치기

`m(...)` 괄호 안에 다섯 개가 순서대로 들어갑니다.

```js
life: m(78, '시내권 도보 생활 가능', '소상공인시장진흥공단 상가정보', '2026-08-20', '월'),
      //  ①   ②                      ③                              ④            ⑤
```

| | 뜻 |
|---|---|
| ① | **점수** 0~100. 높을수록 좋음 |
| ② | **사람 말로 쓴 설명.** 화면에 그대로 나옵니다 |
| ③ | **어디서 가져온 정보인지** (출처) |
| ④ | **언제 기준인지** (기준일) |
| ⑤ | 얼마나 자주 갱신하는지 — `'월'` `'분기'` `'반기'` |

여섯 개 항목의 이름은 이렇습니다: `life`(생활편의) `medical`(의료접근) `transit`(교통) `work`(업무환경) `nature`(자연관광) `cost`(체류비용)

> **`cost`(체류비용)는 점수가 높을수록 "싸다"는 뜻입니다.** 비쌀수록 낮은 점수를 주세요.

### 아직 모르는 항목은?

점수 자리에 `null`을 쓰세요.

```js
work: m(null, '데이터 없음', null, null, '반기'),
```

화면에 "데이터 없음"이라고 정직하게 나오고, 그 항목은 점수 계산에서 빠집니다.
**모르는 걸 0점으로 넣으면 안 됩니다.** 그 지역이 부당하게 나쁘게 나옵니다.

## 카카오톡 채널 연결하기

카카오톡 채널을 만드셨다면, `data.js` 맨 위쪽에서 주소만 넣으면 **모든 화면의 카카오 버튼이 한 번에 연결됩니다.**

```js
const SITE = {
  kakaoChannelUrl: ''   // ← 이 따옴표 안에 주소를 넣으세요
};
```

이렇게 바꾸면 됩니다.

```js
const SITE = {
  kakaoChannelUrl: 'https://pf.kakao.com/_abcdef'
};
```

비워 두면 버튼을 눌렀을 때 "채널은 준비 중입니다"라고 안내가 나오고 이메일 입력을 권합니다.
지금은 비어 있는 상태입니다.

## 화면 문구 고치기

문구는 각 화면 파일(`index.html` 등) 안에 있습니다. **한글 문장만 찾아서 바꾸세요.**
`<` `>` 로 감싸인 부분은 건드리지 마세요.

예를 들어 홈 화면의 큰 제목을 바꾸려면 `index.html`에서 이 부분을 찾습니다.

```html
<h1>여행 말고,<br>한번 살아보세요.</h1>
```

`여행 말고,` 와 `한번 살아보세요.` 만 바꾸면 됩니다. `<h1>` `<br>` `</h1>`은 그대로 두세요.

> 자주 고칠 만한 문구가 어느 화면에 있는지는 [1. 화면 설명서](1_화면-설명서.md)를 참고하세요.

## 이건 건드리지 마세요

`assets` 폴더 안의 **`app.js`, `match.js`, `style.css`** 세 파일은 사이트가 돌아가는 장치입니다.
여기를 고치려면 개발자가 필요합니다.

특히 `match.js`에는 "신청 가능 / 확인 필요 / 대상 아님"을 정하는 규칙이 들어 있습니다.
판정 기준 자체를 바꾸고 싶다면 [3. 판정 규칙 설명](3_판정-규칙-설명.md)을 먼저 읽고, 개발자에게 요청하세요.
