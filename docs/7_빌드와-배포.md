# 7. 빌드와 배포 (2026-10-27 구조)

사이트는 이제 `python build.py` 가 만드는 `dist/` 폴더를 올리는 방식입니다. 저장소에 올라간 파일을 그대로 보여주던 이전 방식과 다르므로, **GitHub Pages 설정을 한 번 바꿔야 합니다.**

## 처음 한 번만

### ① GitHub Pages 를 "GitHub Actions" 로
저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿉니다.
그 뒤로는 `main` 에 푸시할 때마다, 그리고 매일 새벽 5시에 `.github/workflows/build.yml` 이 돌아가 사이트를 다시 만듭니다.
진행 상황은 저장소 **Actions** 탭에서 봅니다. 빨간 X 가 뜨면 그 실행을 열어 로그를 보면 어느 공고 행이 문제인지 적혀 있습니다.

### ② 비밀값 등록
**Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `SHEET_NOTICES_CSV_URL` | 구글 시트 "공고" 탭의 CSV 게시 주소 |
| `SHEET_COMMENTARY_CSV_URL` | "해설" 탭의 CSV 게시 주소 |
| `YOUTHCENTER_API_KEY` | 온통청년 인증키(발급 후) |

구글 시트 게시 주소 얻는 법: 시트에서 **파일 → 공유 → 웹에 게시 → 링크 탭 → 탭 선택, "쉼표로 구분된 값(.csv)" 선택 → 게시** → 나온 주소.
비밀값이 없으면 저장소의 `data/sheet/*.csv` 를 그대로 씁니다.

### ③ (도메인 연결 시) 변수 등록
**Variables** 탭에 `SITE_URL` = `https://도메인`, `BASE_PATH` = 빈 값. 그리고 `config.json` 의 `cname` 에 도메인을 적습니다.
Settings → Pages → Custom domain 에 같은 도메인을 넣고 **Enforce HTTPS** 를 켭니다.
www 와 비www 중 하나로 통일하려면 도메인 업체에서 나머지 하나를 301 로 넘기도록 설정합니다.

## 매번: 공고 고치기
1. 구글 시트에서 공고·해설을 고칩니다(열 설명: `data/sheet/README.md`).
2. 다음 날 새벽 5시에 자동 반영됩니다. 바로 반영하려면 **Actions → build-and-deploy → Run workflow**.
3. 코드나 문구(소개·약관·가이드)를 고쳤다면 `웹사이트 업데이트.bat` 으로 푸시하면 2~3분 뒤 반영됩니다.

## 내 컴퓨터에서 미리 보기
`사이트 열어보기.bat` 두 번 클릭. Python 3 가 설치되어 있어야 합니다(https://www.python.org/downloads/ , 설치 시 "Add python.exe to PATH" 체크).

## Netlify 를 쓸 경우
GitHub Pages 대신 Netlify 를 고르면 `netlify.toml` 이 빌드 명령과 `dist` 폴더를 지정합니다.
Netlify 사이트 설정 → Environment variables 에 위 비밀값 3개를 넣고, 매일 빌드는 **Build hooks** 주소를 만들어 외부에서 하루 한 번 호출합니다(예: GitHub Actions 의 schedule 에서 `curl -X POST 주소`).
이 경우 `.github/workflows/build.yml` 의 deploy 작업은 지우거나 비활성화합니다.

## 온통청년 API 연결 순서
1. 인증키 발급 후 Secrets 에 `YOUTHCENTER_API_KEY` 등록.
2. 제공목록에서 호출 주소·파라미터·응답 필드명을 확인해 `config/youthcenter.json` 을 채웁니다. `field_map` 의 오른쪽 값이 응답 필드명입니다.
3. 대표가 확정한 "정책 분야 → 카테고리" 표를 `category_map` 에 넣습니다. 표에 없는 분야는 건너뛰고 로그에 남습니다.
4. `enabled` 를 `true` 로 바꾸고 워크플로를 수동 실행합니다. 원본은 `data/raw/youthcenter/날짜.json` 에 쌓이고, 전날과 비교한 신규·변경·사라진 정책은 `changes-날짜.json`, 사라진 정책은 `review-needed.json` 에 기록됩니다(바로 삭제하지 않음).
